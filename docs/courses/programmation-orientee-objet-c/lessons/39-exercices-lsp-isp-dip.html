Exercices : LSP, ISP & DIP

codingDurée : 1h

Cette page regroupe deux exercices pour ancrer les principes SOLID, avec un accent particulier sur LSP (substitution de Liskov), ISP (segregation des interfaces) et DIP (inversion des dépendances). Le premier est un exercice de lecture pour repérer les violations, le second est un refactor complet. Le réflexe a acquérir : un seul principe par violation, pas les cinq à la fois.

Mini exercice : identifier la violation SOLID

Objectif

Repérer en lecture quel principe SOLID est viole dans un snippet, et le justifier en une phrase. Pour chaque snippet, indique le principe viole (S, O, L, I ou D) et pourquoi.

Snippet 1

public class Utilisateur
{
    public string Nom { get; set; }
    public string Email { get; set; }

    public void SauverEnBase() { /* ... */ }
    public void EnvoyerEmailBienvenue() { /* ... */ }
    public string GenererCarteVisite() { /* ... */ }
}

Snippet 2

public class CalculReduction
{
    public decimal Calculer(string typeClient, decimal montant)
    {
        if (typeClient == "VIP") return montant * 0.8m;
        else if (typeClient == "Pro") return montant * 0.9m;
        else if (typeClient == "Standard") return montant;
        else if (typeClient == "Etudiant") return montant * 0.85m;
        else return montant;
    }
}

Snippet 3

public class Oiseau
{
    public virtual void Voler() { Console.WriteLine("Je vole"); }
}

public class Manchot : Oiseau
{
    public override void Voler()
    {
        throw new NotSupportedException("Un manchot ne vole pas");
    }
}

Snippet 4

public interface ITravailleur
{
    void Coder();
    void DessinerMaquette();
    void EcrireSpec();
    void TenirReunion();
}

public class Developpeur : ITravailleur
{
    public void Coder() { /* ... */ }
    public void DessinerMaquette() { throw new NotImplementedException(); }
    public void EcrireSpec() { throw new NotImplementedException(); }
    public void TenirReunion() { throw new NotImplementedException(); }
}

Snippet 5

public class RapportMensuel
{
    public void Generer()
    {
        var donnees = new MySqlDatabase().LireVentes();
        // ... formatage
    }
}

Les snippets 3, 4 et 5 illustrent directement les trois principes au coeur de cette page : le manchot qui lève une exception sur Voler() casse la substitution (LSP), l'interface ITravailleur trop large force le developpeur a implémenter des méthodes vides (ISP), et le rapport qui instancie lui-même MySqlDatabase dependant d'une classe concrète (DIP). L'énoncé complet est disponible dans le dépôt : l'énoncé.

Exercice principal : refactor SOLID

Objectif

Décomposer une classe qui viole SRP et DIP. Extraire les responsabilités, inverser les dépendances. La classe de départ fait trois choses (elle lit en base, génère un PDF, envoie un email) et dépend de classes concrètes (SqlConnection, File, SmtpClient). Elle est impossible à tester sans base ni serveur SMTP.

Code de départ

public class FactureService
{
    public void TraiterFacture(int factureId)
    {
        // Lecture en base
        var connection = new SqlConnection("Server=...;Database=...");
        connection.Open();
        var cmd = new SqlCommand($"SELECT * FROM Factures WHERE Id={factureId}", connection);
        var reader = cmd.ExecuteReader();
        reader.Read();
        var montant = (decimal)reader["Montant"];
        var emailClient = (string)reader["Email"];
        connection.Close();

        // Generation PDF
        var pdfPath = $"factures/facture-{factureId}.pdf";
        File.WriteAllText(pdfPath, $"Facture {factureId} : {montant} EUR");

        // Envoi email
        var smtp = new SmtpClient("smtp.entreprise.com");
        var mail = new MailMessage("noreply@entreprise.com", emailClient)
        {
            Subject = $"Votre facture {factureId}",
            Body = "Veuillez trouver votre facture en piece jointe."
        };
        mail.Attachments.Add(new Attachment(pdfPath));
        smtp.Send(mail);
    }
}

Étapes

  1. Crée une classe Facture (modèle) avec Id, Montant, EmailClient.
  2. Crée trois interfaces :
    • IFactureRepository avec Facture LireParId(int id)
    • IPdfGenerator avec string Generer(Facture facture) qui retourne le chemin du PDF
    • IEmailService avec void Envoyer(string destinataire, string sujet, string corps, string pieceJointe)
  3. Crée les trois implémentations concrètes : SqlFactureRepository, FilePdfGenerator, SmtpEmailService. Chacune reçoit sa config (connection string, host SMTP) dans son constructeur.
  4. Refactore FactureService pour qu'il reçoive les trois interfaces dans son constructeur. La méthode TraiterFacture orchestre les appels.
  5. Dans Program.cs, instancie les trois implémentations et injecte-les dans FactureService.

Chaque interface correspond a une dépendance externe : c'est l'application directe de DIP. Le service de haut niveau ne dépend plus que d'abstractions, et chaque implémentation reste petite et focalisee, dans l'esprit d'ISP.

Bonus

Crée une implémentation alternative FakeEmailService qui se contente d'imprimer en console. Passe-la a FactureService pour tester sans envoyer d'email réel. C'est exactement le benefice de l'inversion des dépendances : on substitue une implémentation par une autre sans toucher au service.

Compte environ 15 minutes : traite les étapes 1 a 5 d'abord, puis le bonus s'il te reste du temps. L'énoncé complet est disponible dans le dépôt : l'énoncé.
