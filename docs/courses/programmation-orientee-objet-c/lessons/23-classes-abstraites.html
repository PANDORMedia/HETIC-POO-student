Classes abstraites

readingDuration: 20 min

Les classes abstraites

Une classe abstraite est une classe incomplète que l'on ne peut pas instancier directement. Elle sert de modèle pour ses classes dérivées.

Contrairement à une classe concrète, elle peut contenir des méthodes abstraites : des signatures sans implémentation que les classes dérivées doivent implémenter.

// Syntaxe d'une classe abstraite
public abstract class Media
{
    public string Titre { get; set; }
    public int Annee { get; set; }

    // Méthode concrète : fournit une implémentation par défaut
    public virtual string GetInfo() => $"{Titre} ({Annee})";

    // Méthode abstraite : PAS de corps, les dérivées DOIVENT l'implémenter
    public abstract decimal CalculerPrix();
    public abstract string GetTypeMedia();
}

// Erreur : impossible d'instancier une classe abstraite
// var media = new Media(); // ❌ Compilation error

public class Film : Media
{
    public string Realisateur { get; set; }
    public int DureeMinutes { get; set; }

    // Obligation d'implémenter les méthodes abstraites
    public override decimal CalculerPrix() => DureeMinutes > 120 ? 14.99m : 9.99m;

    public override string GetTypeMedia() => "Film";
}

Abstract vs Virtual

Caractéristiqueabstractvirtual
A un corps ?Non (signature uniquement)Oui (implémentation par défaut)
Implémentation obligatoire dans les dérivées ?OuiNon (le défaut suffit)
La classe doit être abstraite ?OuiNon

Choisissez abstract quand chaque dérivée doit fournir sa propre logique. Choisissez virtual quand un comportement par défaut a du sens.

// Le Template Method Pattern avec les classes abstraites
public abstract class Media
{
    public string Titre { get; set; }
    public int Annee { get; set; }

    // Template method : algorithme fixe, étapes variables
    public string GenererFiche()
    {
        return $"=== {GetTypeMedia()} ===\n" +
               $"Titre : {Titre}\n" +
               $"Année : {Annee}\n" +
               $"Détails : {GetDetails()}\n" +
               $"Prix : {CalculerPrix():C}";
    }

    // Méthodes que les dérivées doivent fournir
    protected abstract string GetTypeMedia();
    protected abstract string GetDetails();
    public abstract decimal CalculerPrix();
}

public class Film : Media
{
    public string Realisateur { get; set; }
    public int DureeMinutes { get; set; }

    protected override string GetTypeMedia() => "Film";
    protected override string GetDetails() => $"Réalisateur : {Realisateur}, Durée : {DureeMinutes} min";
    public override decimal CalculerPrix() => DureeMinutes > 120 ? 14.99m : 9.99m;
}

var film = new Film { Titre = "Dune", Annee = 2021, Realisateur = "Villeneuve", DureeMinutes = 155 };
Console.WriteLine(film.GenererFiche());
// === Film ===
// Titre : Dune
// Année : 2021
// Détails : Réalisateur : Villeneuve, Durée : 155 min
// Prix : 14,99 €

Quand utiliser une classe abstraite

Utilisez une classe abstraite quand :

  • Vous avez un code commun partagé entre plusieurs dérivées
  • Certaines méthodes doivent être implémentées par chaque dérivée
  • Vous voulez définir un algorithme (template method) avec des étapes variables
  • Il existe une vraie relation « est un » entre la base et les dérivées

N'utilisez pas de classe abstraite si vous n'avez besoin que d'un contrat sans code partagé (utilisez une interface à la place).

// Hiérarchie complète pour le gestionnaire de films
public abstract class Media
{
    private static int _compteur = 0;
    public int Id { get; }
    public string Titre { get; set; }
    public int Annee { get; set; }

    protected Media(string titre, int annee)
    {
        Id = ++_compteur;
        Titre = titre;
        Annee = annee;
    }

    public abstract string GetTypeMedia();
    public abstract decimal CalculerPrix();

    public override string ToString() => $"[{Id}] {GetTypeMedia()} : {Titre} ({Annee}) - {CalculerPrix():C}";
}

public class Film : Media
{
    public string Realisateur { get; set; }
    public int DureeMinutes { get; set; }
    public string Genre { get; set; }

    public Film(string titre, int annee, string realisateur, int duree, string genre)
        : base(titre, annee)
    {
        Realisateur = realisateur;
        DureeMinutes = duree;
        Genre = genre;
    }

    public override string GetTypeMedia() => "Film";
    public override decimal CalculerPrix() => DureeMinutes > 120 ? 14.99m : 9.99m;
}

public class Serie : Media
{
    public int Saisons { get; set; }

    public Serie(string titre, int annee, int saisons) : base(titre, annee)
        => Saisons = saisons;

    public override string GetTypeMedia() => "Série";
    public override decimal CalculerPrix() => Saisons * 7.99m;
}

MCQ

Que se passe-t-il si une classe dérivée n'implémente pas toutes les méthodes abstraites de sa classe de base ?

  1. Erreur de compilation
  2. La méthode abstraite est appelée au runtime et ne fait rien
  3. Un comportement par défaut est utilisé
  4. La classe dérivée devient automatiquement abstraite
Explanation

Soit la classe dérivée implémente toutes les méthodes abstraites, soit elle doit elle-même être déclarée abstract.

Points clés

  • abstract empêche l'instanciation directe
  • Les méthodes abstraites n'ont pas de corps et doivent être implémentées par les dérivées
  • Combine code commun (méthodes concrètes) et contrat (méthodes abstraites)
  • Le Template Method Pattern est un usage classique
  • Préférez une classe abstraite quand vous avez de l'état et du code partagé
