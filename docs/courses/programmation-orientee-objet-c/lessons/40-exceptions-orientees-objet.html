Exceptions orientées objet

slidesDurée : 30 min

Une exception est un objet

Quand une opération ne peut pas continuer, elle lance un signal type. Le code qui appelle décide quoi faire. Une exception n'est pas un simple code d'erreur : c'est un objet qui porte un type, un message, une stack trace et éventuellement une innerException.

Pourquoi des exceptions ?

Le style des codes de retour hérite du C : chaque appel renvoie un entier que l'appelant doit vérifier à la main.

int result = ouvrirFichier(chemin);
if (result == ERR_NOT_FOUND) { ... }
else if (result == ERR_PERMISSION) { ... }
else if (result < 0) { ... }
// Si tu oublies de verifier, ton code
// continue en silence avec un etat pourri.

Avec les exceptions, l'erreur ne peut pas être ignoree par accident.

try
{
    var stream = File.Open(chemin);
}
catch (FileNotFoundException ex) { ... }
catch (UnauthorizedAccessException ex) { ... }
// Si tu oublies le catch, l'exception remonte.
// Impossible de l'ignorer en silence.

Le mécanisme : détecter, propager, traiter

Le code qui détecte le problème ne se débrouille pas seul : il lève l'alarme et laisse quelqu'un d'autre s'en occuper.

  • Le code qui détecte le problème fait throw.
  • L'exception se propage dans la pile d'appels.
  • Un bloc catch plus haut l'intercepte.
  • Le code qui sait quoi faire reagit.

L'objet exception transporte toute l'information utile entre les deux : type, message, contexte.

La hiérarchie d'Exception en .NET

Toutes les exceptions derivent de la classe racine Exception. Quelques types courants a connaître :

  • SystemException : NullReferenceException, IndexOutOfRangeException, InvalidOperationException.
  • ArgumentException : ArgumentNullException, ArgumentOutOfRangeException.
  • IOException : FileNotFoundException, DirectoryNotFoundException.

Tes exceptions métier (par exemple VehiculeIndisponibleException ou SoldeInsuffisantException) héritent de Exception. Conventions : un suffixe en "Exception", et un constructeur qui accepte un message et idéalement une innerException.

Syntaxe : try / catch / finally

FileStream stream = null;
try
{
    stream = File.Open(chemin);
    Traiter(stream);
}
catch (FileNotFoundException ex)
{
    Log.Warn($"Fichier absent : {chemin}");
}
catch (IOException ex)
{
    Log.Error("Erreur IO", ex);
    throw;
}
finally
{
    stream?.Close();
}

Les règles à retenir :

  • Plusieurs catch, ordonnes du plus spécifique au plus général.
  • finally s'exécute toujours, même après un throw ou un return.
  • throw; sans argument relance l'exception en gardant la stack trace.
  • using remplace souvent try / finally pour les types IDisposable.

Créer une exception métier

Un type dédié permet de transporter le contexte de l'erreur et d'être intercepte précisément par l'appelant.

public class SoldeInsuffisantException : Exception
{
    public decimal SoldeActuel { get; }
    public decimal MontantDemande { get; }

    public SoldeInsuffisantException(
        decimal solde, decimal demande)
        : base($"Solde {solde:C} insuffisant " +
               $"pour retrait de {demande:C}")
    {
        SoldeActuel = solde;
        MontantDemande = demande;
    }
}

Cote emetteur, on lève l'exception dès que l'invariant est viole :

public void Retirer(decimal montant)
{
    if (montant > _solde)
        throw new SoldeInsuffisantException(
            _solde, montant);
    _solde -= montant;
}

Cote appelant, on exploite les propriétés de l'objet exception :

try
{
    compte.Retirer(500);
}
catch (SoldeInsuffisantException ex)
{
    var manque = ex.MontantDemande - ex.SoldeActuel;
    Console.WriteLine($"Manque {manque:C}");
}

Anti-patterns a éviter

Anti-patternProblèmeÀ faire
Catch silencieux : catch { /* nothing */ } Tu masques tous les bugs. Si tu catch, fais quelque chose.
throw ex; dans le catch La stack trace est perdue. Utilise throw; sans argument pour la préserver.
Exception en flux normal : catch { return 0; } Les exceptions coûtent cher. Utilise int.TryParse.
Exception générique : throw new Exception("...") L'appelant ne peut pas catch spécifiquement. Crée un type métier dédié.
