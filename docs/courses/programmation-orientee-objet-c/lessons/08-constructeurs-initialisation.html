Constructeurs & initialisation

Ce document approfondit les concepts présentés dans le deck. Tu y trouveras les syntaxes avancées et les nuances de chaque approche d'initialisation.

Le problème du constructeur par défaut

Sans constructeur explicite, C# fournit un constructeur par défaut sans paramètres. Les champs restent à leur valeur par défaut (null pour les références, 0 pour les entiers) :

public class Film
{
    public string titre;
    public string realisateur;
    public int annee;
}

// Utilisation
Film f = new Film();
f.titre = "Inception";     // Obligé d'assigner champ par champ
f.realisateur = "Nolan";
f.annee = 2010;
// Risque : un Film sans titre est possible !
Console.WriteLine(f.titre); // OK
Console.WriteLine(f.realisateur); // OK

Constructeur paramétré

Un constructeur permet de forcer l'initialisation des champs au moment de la création :

public class Film
{
    public string titre;
    public string realisateur;
    public int annee;

    // Constructeur paramétré
    public Film(string titre, string realisateur, int annee)
    {
        this.titre = titre;
        this.realisateur = realisateur;
        this.annee = annee;
    }

    public void Afficher()
    {
        Console.WriteLine($"{titre} ({annee}) - {realisateur}");
    }
}

// Utilisation
Film f = new Film("Inception", "Christopher Nolan", 2010);
f.Afficher(); // Inception (2010) - Christopher Nolan

Le mot-clé this

Dans un constructeur (ou une méthode), this fait référence à l'objet en cours de construction. Quand le paramètre a le même nom qu'un champ, this lève l'ambiguité :

  • this.titre : le champ de l'objet
  • titre : le paramètre du constructeur

Si les noms sont différents, this est optionnel mais reste explicite.

Surcharge de constructeurs

Une classe peut avoir plusieurs constructeurs avec des signatures différentes. C'est la surcharge (overloading) :

public class Film
{
    public string titre;
    public string realisateur;
    public int annee;
    public string genre;

    // Constructeur complet
    public Film(string titre, string realisateur, int annee, string genre)
    {
        this.titre = titre;
        this.realisateur = realisateur;
        this.annee = annee;
        this.genre = genre;
    }

    // Constructeur simplifié (sans genre)
    public Film(string titre, string realisateur, int annee)
        : this(titre, realisateur, annee, "Non défini")
    {
        }

    public void Afficher()
    {
        Console.WriteLine($"{titre} ({annee}) - {realisateur} [{genre}]");
    }
}

Film f1 = new Film("Inception", "Nolan", 2010, "Sci-Fi");
Film f2 = new Film("Parasite", "Bong", 2019);
f1.Afficher(); // Inception (2010) - Nolan [Sci-Fi]
f2.Afficher(); // Parasite (2019) - Bong [Non défini]

Syntaxe d'initialisation d'objet

C# propose une syntaxe concise pour initialiser les propriétés publiques à la création :

// Avec constructeur paramétré classique
Film f1 = new Film("Dune", "Villeneuve", 2021);

// Avec initialisateur d'objet (si constructeur sans paramètres disponible)
// Pas possible ici car on a défini un constructeur paramétré sans paramètres

// La syntaxe fonctionne avec un constructeur par défaut :
public class Categorie
{
    public string nom;
    public string description;
}

Categorie cat = new Categorie
{
    nom = "Science-Fiction",
    description = "Films de science-fiction et fantastique"
};

Constructeurs primaires (C# 12 / .NET 8)

Nouveauté de C# 12 : les primary constructors permettent de déclarer les paramètres directement dans l'en-tête de la classe. Plus besoin de corps de constructeur explicite pour les cas simples :

// Constructeur primaire : paramètres dans la déclaration de classe
public class Film(string titre, string realisateur, int annee)
{
    public string Titre => titre;
    public string Realisateur => realisateur;
    public int Annee => annee;

    public void Afficher()
    {
        Console.WriteLine($"{Titre} ({Annee}) - {Realisateur}");
    }
}

// Utilisation
Film f = new Film("Oppenheimer", "Nolan", 2023);
f.Afficher();

Quand utiliser quoi ?

ApprocheQuand l'utiliser
Constructeur par défautObjets simples, initialisation externe acceptable
Constructeur paramétréQuand des champs sont obligatoires à la création
SurchargeQuand plusieurs façons de créer l'objet sont utiles
Initialisateur d'objetQuand beaucoup de champs optionnels
Constructeur primaireC# 12+ pour les classes simples, DTOs, records

Points clés

  • Le constructeur par défaut existe tant que tu n'en définis aucun.
  • Un constructeur paramétré garantit l'intégrité de l'objet dès sa création.
  • :this() permet de chaîner les constructeurs et éviter la duplication.
  • Les constructeurs primaires (C# 12) sont parfaits pour les cas simples.
  • Dans le gestionnaire de films, le constructeur de Film garantira que titre et realisateur sont toujours fournis.
