Exercices : Exceptions OO

codingDurée : 1h

Deux exercices pour mettre en pratique la gestion des exceptions en C#. Le premier est un exercice de lecture qui demande de prédire le flux d'exécution dans un try / catch / finally. Le second consiste à modéliser une exception métier qui transporte du contexte exploitable côté appelant.

Mini exercice : prédire le flux d'exception

Objectif : maîtriser l'ordre d'exécution dans un try / catch / finally, et comprendre l'enchaînement entre les catch typés et la propagation.

Pour chacun des quatre cas ci-dessous, prédis :

  • ce qui s'affiche dans la console ;
  • si une exception s'échappe de la méthode, et son type.

Garde en tête deux règles : le bloc finally s'exécute toujours, même lorsqu'une exception est levée et même lorsqu'un return est rencontré ; un catch n'attrape que les exceptions dont le type correspond.

Cas A

static void CasA()
{
    try
    {
        Console.WriteLine("1");
        throw new InvalidOperationException("oops");
    }
    catch (InvalidOperationException)
    {
        Console.WriteLine("2");
    }
    finally
    {
        Console.WriteLine("3");
    }
    Console.WriteLine("4");
}

Cas B

static void CasB()
{
    try
    {
        Console.WriteLine("1");
        throw new InvalidOperationException("oops");
    }
    catch (ArgumentException)
    {
        Console.WriteLine("2");
    }
    finally
    {
        Console.WriteLine("3");
    }
    Console.WriteLine("4");
}

Cas C

static int CasC()
{
    try
    {
        Console.WriteLine("1");
        return 10;
    }
    finally
    {
        Console.WriteLine("2");
    }
}

Cas D

static void CasD()
{
    try
    {
        try
        {
            throw new InvalidOperationException("inner");
        }
        catch (InvalidOperationException ex)
        {
            Console.WriteLine("A");
            throw new ArgumentException("wrapped", ex);
        }
    }
    catch (Exception ex)
    {
        Console.WriteLine($"B: {ex.GetType().Name}");
        Console.WriteLine($"Inner: {ex.InnerException?.GetType().Name}");
    }
}

Le cas D illustre le chaînage : une exception attrapée puis renvoyée enveloppée dans une autre, qui conserve la première via InnerException. Compte cinq minutes, puis compare ta prédiction avec l'exécution réelle. L'l'énoncé complet est disponible dans le dépôt.

Exercice principal : exception métier

Objectif : modéliser une exception métier qui transporte du contexte exploitable côté appelant. Tu codes un mini système bancaire.

Étapes

  1. Une classe Compte avec :
    • Numero : string ;
    • Titulaire : string ;
    • Solde : decimal, en lecture seule depuis l'extérieur ;
    • un constructeur Compte(string numero, string titulaire, decimal soldeInitial) qui refuse un solde initial négatif.
  2. Une méthode Crediter(decimal montant) qui ajoute au solde. Elle refuse les montants négatifs ou nuls avec une ArgumentOutOfRangeException.
  3. Une exception SoldeInsuffisantException qui :
    • hérite de Exception ;
    • porte deux propriétés publiques : SoldeActuel (decimal) et MontantDemande (decimal) ;
    • a un constructeur SoldeInsuffisantException(decimal solde, decimal demande) qui construit un message lisible et stocke les deux valeurs ;
    • expose une propriété calculée MontantManquant qui retourne MontantDemande - SoldeActuel.
  4. Une méthode Retirer(decimal montant) sur Compte qui :
    • refuse les montants négatifs ou nuls (ArgumentOutOfRangeException) ;
    • lance SoldeInsuffisantException si le solde ne suffit pas ;
    • sinon, débite le compte.
  5. Dans Program.cs, crée un compte avec 100 EUR. Crédite 50, retire 30, puis affiche le solde. Tente ensuite un retrait de 500 dans un try / catch. Dans le catch, affiche un message qui utilise MontantManquant.

Code de départ pour l'exception

Le coeur de l'exercice est la classe d'exception. Elle hérite de Exception et expose le contexte métier sous forme de propriétés, ce qui permet à l'appelant de réagir précisément.

public class SoldeInsuffisantException : Exception
{
    public decimal SoldeActuel { get; }
    public decimal MontantDemande { get; }

    public SoldeInsuffisantException(decimal solde, decimal demande)
        : base($"Solde insuffisant : solde {solde}, demande {demande}.")
    {
        SoldeActuel = solde;
        MontantDemande = demande;
    }

    public decimal MontantManquant => MontantDemande - SoldeActuel;
}

Côté appelant, le catch typé récupère l'objet exception et lit ses propriétés :

try
{
    compte.Retirer(500m);
}
catch (SoldeInsuffisantException ex)
{
    Console.WriteLine($"Retrait refusé. Il manque {ex.MontantManquant} EUR.");
}

Bonus

Ajoute une méthode Virer(decimal montant, Compte destinataire) qui débite ce compte puis crédite l'autre. Si la deuxième opération échoue, le compte source doit revenir à son état initial.

Compte quinze minutes : traite les étapes 1 à 5 d'abord, puis le bonus si tu as le temps. L'l'énoncé complet est disponible dans le dépôt.
