Encapsulation & Propriétés

Ce document approfondit les concepts du deck. Tu y trouveras les syntaxes avancées, les patterns de validation et les nuances entre les différentes formes de propriétés.

Pourquoi encapsuler ?

Imagine une classe Film où tous les champs sont publics. N'importe qui peut écrire :

Film f = new Film();
f.annee = -500;  // Absurde mais possible
f.titre = "";      // Vide mais accepté

L'encapsulation consiste à protéger l'état interne d'un objet en contrôlant comment les données sont lues et modifiées. Le principe est simple : les champs sont private, l'accès se fait par des propriétés publiques qui valident les valeurs.

Access modifiers

C# propose 4 niveaux de visibilité pour les membres d'une classe :

ModificateurPortée
publicAccessible depuis n'importe où
privateAccessible uniquement depuis la classe elle-même
protectedAccessible depuis la classe et ses sous-classes
internalAccessible depuis le même assembly (projet)

La règle par défaut : les champs sont private, les propriétés et méthodes sont public si elles font partie du contrat de la classe.

Propriétés complètes (full properties)

Une propriété complète combine un backing field privé, un getter et un setter :

public class Film
{
    private int _annee;

    public int Annee
    {
        get { return _annee; }
        set
        {
            if (value < 1888 || value > DateTime.Now.Year + 5)
                throw new ArgumentException($"Annee invalide : {value}");
            _annee = value;
        }
    }
}

// Utilisation
Film f = new Film();
f.Annee = 2010;    // OK
// f.Annee = 1800; // Exception !

Le mot-clé value dans le setter représente la valeur que l'appelant essaie d'assigner. C'est un paramètre implicite de type int ici.

Auto-proprietes

Quand tu n'as pas besoin de logique de validation, les auto-propriétés sont plus concises. Le compilateur génère le backing field automatiquement :

public class Film
{
    public string Titre { get; set; }  // Auto-propriété
    public string Realisateur { get; set; }
    public int Annee { get; set; }
}

Proprietes calculees (read-only)

Une propriété sans setter est en lecture seule. Idéal pour les valeurs dérivées :

public class Film
{
    public int Annee { get; set; }

    // Propriété calculée (get uniquement)
    public int Age => DateTime.Now.Year - Annee;
}

Film f = new Film();
f.Annee = 2010;
Console.WriteLine($"Ce film a {f.Age} ans"); // Ce film a 16 ans

Init-only setters

Le modificateur init permet d'assigner une propriété uniquement à la création de l'objet. Après, elle devient immuable :

public class Film
{
    public string Titre { get; init; }
    public string Realisateur { get; init; }
    public int Annee { get; init; }
}

Film f = new Film
{
    Titre = "Inception",
    Realisateur = "Nolan",
    Annee = 2010
};

// f.Titre = "Tenet";  // Erreur de compilation ! init-only

Le modificateur required

En C# 11+, required force l'appelant à fournir une valeur à la création. Combine bien avec init :

public class Film
{
    public required string Titre { get; init; }
    public required string Realisateur { get; init; }
    public int Annee { get; init; } = 2024;  // Valeur par défaut
}

Film f = new Film
{
    Titre = "Dune",
    Realisateur = "Villeneuve"
    // Annee prend 2024 par défaut
};

Recapitulatif des formes de proprietes

FormeQuand l'utiliser
Full property + validationQuand la donnée doit etre validee
Auto-propriétéAcces simple sans logique
Propriété calculéeValeur derivée d'autres champs
initImmuable apres creation
requiredChamp obligatoire a la creation
required + initChamp obligatoire et immuable

Points cles

  • Les champs sont private, l'acces se fait par des proprietes public.
  • Le setter permet de valider les valeurs et proteger l'integrite de l'objet.
  • Les auto-proprietes suffisent quand il n'y a pas de logique de validation.
  • Les proprietes calculees derivent leur valeur dynamiquement.
  • init rend une propriete immuable apres creation.
  • required force la fourniture d'une valeur a l'initialisation.
  • Dans le gestionnaire de films, Annee sera validee et Age sera une propriete calculee.
