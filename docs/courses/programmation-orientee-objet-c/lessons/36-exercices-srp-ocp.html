Exercices : SRP & OCP

codingDurée : 1h

Cette page rassemble deux exercices pour mettre en pratique les principes SOLID, en particulier la responsabilité unique (SRP) et l'inversion des dépendances (DIP). Le premier est un exercice de lecture rapide, le second un refactoring complet. Commence par le mini exercice, puis enchaine sur le refactoring principal.

Mini exercice : identifier la violation SOLID

Objectif

Repérer en lecture quel principe SOLID est viole dans un snippet, et le justifier en une phrase. Le réflexe a acquérir : un seul principe par violation, pas les cinq à la fois.

Énoncé

Pour chacun des cinq snippets ci-dessous, indique le principe viole (S, O, L, I ou D) et explique pourquoi en une phrase.

Snippet 1

public class Utilisateur
{
    public string Nom { get; set; }
    public string Email { get; set; }

    public void SauverEnBase() { /* ... */ }
    public void EnvoyerEmailBienvenue() { /* ... */ }
    public string GenererCarteVisite() { /* ... */ }
}

Snippet 2

public class CalculReduction
{
    public decimal Calculer(string typeClient, decimal montant)
    {
        if (typeClient == "VIP") return montant * 0.8m;
        else if (typeClient == "Pro") return montant * 0.9m;
        else if (typeClient == "Standard") return montant;
        else if (typeClient == "Etudiant") return montant * 0.85m;
        else return montant;
    }
}

Snippet 3

public class Oiseau
{
    public virtual void Voler() { Console.WriteLine("Je vole"); }
}

public class Manchot : Oiseau
{
    public override void Voler()
    {
        throw new NotSupportedException("Un manchot ne vole pas");
    }
}

Snippet 4

public interface ITravailleur
{
    void Coder();
    void DessinerMaquette();
    void EcrireSpec();
    void TenirReunion();
}

public class Developpeur : ITravailleur
{
    public void Coder() { /* ... */ }
    public void DessinerMaquette() { throw new NotImplementedException(); }
    public void EcrireSpec() { throw new NotImplementedException(); }
    public void TenirReunion() { throw new NotImplementedException(); }
}

Snippet 5

public class RapportMensuel
{
    public void Generer()
    {
        var donnees = new MySqlDatabase().LireVentes();
        // ... formatage
    }
}

Pistes de correction

SnippetPrincipe violePourquoi
1SRPLa classe mélange le modèle, la persistance, l'envoi d'email et la génération d'un visuel : autant de raisons de changer.
2OCPAjouter un type de client oblige a modifier la chaine de if, au lieu d'étendre le comportement sans toucher au code existant.
3LSPUn Manchot ne peut pas remplacer un Oiseau sans casser le contrat, puisque Voler lève une exception.
4ISPL'interface est trop large : le Developpeur est force d'implémenter des méthodes qui ne le concernent pas.
5DIPLa classe dépend directement d'une implémentation concrète (MySqlDatabase) au lieu d'une abstraction injectée.

Exercice principal : refactor SOLID

Objectif

Décomposer une classe qui viole SRP et DIP. Extraire les responsabilités, puis inverser les dépendances pour rendre le tout testable.

Code de départ

public class FactureService
{
    public void TraiterFacture(int factureId)
    {
        // Lecture en base
        var connection = new SqlConnection("Server=...;Database=...");
        connection.Open();
        var cmd = new SqlCommand($"SELECT * FROM Factures WHERE Id={factureId}", connection);
        var reader = cmd.ExecuteReader();
        reader.Read();
        var montant = (decimal)reader["Montant"];
        var emailClient = (string)reader["Email"];
        connection.Close();

        // Generation PDF
        var pdfPath = $"factures/facture-{factureId}.pdf";
        File.WriteAllText(pdfPath, $"Facture {factureId} : {montant} EUR");

        // Envoi email
        var smtp = new SmtpClient("smtp.entreprise.com");
        var mail = new MailMessage("noreply@entreprise.com", emailClient)
        {
            Subject = $"Votre facture {factureId}",
            Body = "Veuillez trouver votre facture en piece jointe."
        };
        mail.Attachments.Add(new Attachment(pdfPath));
        smtp.Send(mail);
    }
}

Cette classe fait trois choses (elle lit en base, génère un PDF, envoie un email) et dépend de classes concrètes (SqlConnection, File, SmtpClient). Elle est impossible à tester sans une vraie base et un vrai serveur SMTP.

Étapes

  1. Crée une classe Facture (le modèle) avec Id, Montant et EmailClient.
  2. Crée trois interfaces :
    • IFactureRepository avec Facture LireParId(int id)
    • IPdfGenerator avec string Generer(Facture facture) qui retourne le chemin du PDF
    • IEmailService avec void Envoyer(string destinataire, string sujet, string corps, string pieceJointe)
  3. Crée les trois implémentations concrètes : SqlFactureRepository, FilePdfGenerator et SmtpEmailService. Chacune reçoit sa configuration (chaine de connexion, hote SMTP) dans son constructeur.
  4. Refactore FactureService pour qu'il reçoive les trois interfaces dans son constructeur. La méthode TraiterFacture se contente alors d'orchestrer les appels.
  5. Dans Program.cs, instancie les trois implémentations et injecte-les dans FactureService.

Cible après refactoring

public class FactureService
{
    private readonly IFactureRepository _repository;
    private readonly IPdfGenerator _pdfGenerator;
    private readonly IEmailService _emailService;

    public FactureService(
        IFactureRepository repository,
        IPdfGenerator pdfGenerator,
        IEmailService emailService)
    {
        _repository = repository;
        _pdfGenerator = pdfGenerator;
        _emailService = emailService;
    }

    public void TraiterFacture(int factureId)
    {
        var facture = _repository.LireParId(factureId);
        var pdfPath = _pdfGenerator.Generer(facture);
        _emailService.Envoyer(
            facture.EmailClient,
            $"Votre facture {facture.Id}",
            "Veuillez trouver votre facture en piece jointe.",
            pdfPath);
    }
}

Bonus

Crée une implémentation alternative FakeEmailService qui se contente d'imprimer le message en console. Passe-la a FactureService pour tester l'orchestration sans envoyer d'email réel. C'est tout l'intérêt du DIP : une fois la dépendance abstraite, on remplace l'implémentation sans toucher au service.

Pour aller plus loin

Le mini exercice et le refactoring complet sont disponibles dans le dépôt : l'énoncé du mini exercice et l'énoncé du refactoring. Concentre-toi d'abord sur les étapes 1 a 5, puis sur le bonus si tu as le temps.
