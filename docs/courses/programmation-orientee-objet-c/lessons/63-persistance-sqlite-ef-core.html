Persistance : SQLite et Entity Framework Core

readingDurée : 25 min

Jusqu'ici, la démo ASP.NET stockait ses données en mémoire ou dans un fichier. Pour une application qui doit survivre à un redémarrage, il faut une vraie base de données. On utilise ici SQLite, une base SQL légère, pilotée depuis le C# par Entity Framework Core. C'est exactement ce que fait la démo aspnet-mvc.

SQLite et EF Core : à quoi servent-ils

SQLite est une base SQL contenue dans un seul fichier .db. Il n'y a pas de serveur à installer ni à lancer : la base est embarquée et ne demande aucune configuration. C'est idéal pour le développement et les petites applications. Et comme c'est du SQL standard, on peut migrer vers PostgreSQL plus tard sans réécrire la logique.

Entity Framework Core est l'ORM (Object-Relational Mapping) officiel de .NET. On écrit des classes C#, et EF Core génère le SQL et crée les tables. Une classe correspond à une table, une propriété à une colonne, et les requêtes s'écrivent en LINQ (_db.Cars.Where(c => c.Available)) plutôt qu'en SQL à la main.

Installer les packages

Deux packages NuGet pour le projet, et un outil en ligne de commande à installer une seule fois sur la machine :

# dans le dossier du projet
dotnet add package Microsoft.EntityFrameworkCore.Sqlite   # le provider SQLite
dotnet add package Microsoft.EntityFrameworkCore.Design    # requis pour les migrations

# une seule fois sur ta machine : l'outil de migration
dotnet tool install --global dotnet-ef

Le DbContext : la porte vers la base

Le DbContext représente la session avec la base. On en hérite et on déclare un DbSet<T> par table. Le constructeur reçoit ses options (dont la chaine de connexion) par injection.

using Microsoft.EntityFrameworkCore;

public class AppDbContext : DbContext
{
    public AppDbContext(DbContextOptions<AppDbContext> options) : base(options) { }

    // Un DbSet par table. EF deduit les colonnes a partir des proprietes.
    public DbSet<CarBrand> CarBrands { get; set; }
    public DbSet<CarModel> CarModels { get; set; }
    public DbSet<Car> Cars { get; set; }
}

Les relations entre entités

Une marque possède plusieurs modèles, et un modèle plusieurs voitures : deux relations un-à-plusieurs. EF Core les déduit par convention, à partir des clés étrangères et des propriétés de navigation.

public class CarBrand
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public List<CarModel> Models { get; set; } = new();   // une marque, plusieurs modeles
}

public class CarModel
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public int CarBrandId { get; set; }                   // cle etrangere vers la marque
    public CarBrand CarBrand { get; set; } = null!;       // propriete de navigation
    public List<Car> Cars { get; set; } = new();          // un modele, plusieurs voitures
}

Brancher la base dans Program.cs

On indique la chaine de connexion dans appsettings.json, puis on enregistre le contexte dans le conteneur d'injection de dépendances :

// appsettings.json
{
  "ConnectionStrings": {
    "Default": "Data Source=rental.db"    // un simple fichier a la racine du projet
  }
}
// Program.cs
builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlite(builder.Configuration.GetConnectionString("Default")));

AddDbContext enregistre le contexte avec une durée de vie Scoped, soit une instance par requête HTTP, ce qui est la portée recommandée pour un DbContext.

Créer la base avec les migrations

Une migration est un script généré qui décrit la structure des tables. On en crée une, puis on l'applique pour fabriquer le fichier .db. À chaque évolution du modèle, on ajoute une nouvelle migration.

dotnet ef migrations add InitialCreate   # genere le code decrivant le schema
dotnet ef database update                # cree rental.db et ses tables

Le dépôt accède ensuite à la base via le contexte, en gardant la même interface que les autres dépôts (le pattern repository vu dans la démo). Changer de stockage revient à changer une seule ligne dans Program.cs :

public class CarSqlLiteRepository : ICarRepository
{
    private readonly AppDbContext _db;
    public CarSqlLiteRepository(AppDbContext db) => _db = db;

    public List<Car> GetAllCars() => _db.Cars.ToList();

    public bool Add(Car c)
    {
        _db.Cars.Add(c);
        _db.SaveChanges();   // ecrit reellement en base
        return true;
    }
}
