Quiz : Évaluation finale

quizDurée : 20 min

Ce quiz final reprend les notions vues sur tout le cours : POO, principes SOLID, architecture MVC et injection de dépendances. Dix questions a choix multiple, une seule réponse correcte par question. Prends le temps de justifier mentalement ton choix avant de dérouler l'explication.

QCM1 min

Dans le pattern MVC, quel composant reçoit la requête HTTP, interroge le model et choisit la view ?

  1. La view
  2. Le model
  3. Le controller
  4. Le routeur
Explication

Le controller est l'orchestrateur : il reçoit la requête, demande au model les données, choisit la view et renvoie la réponse. Le model porte les données et la logique métier, la view se charge du rendu.

QCM1 min

Avec la convention de routage par défaut, a quelle action correspond l'URL /Voitures/Detail/5 ?

  1. VoituresController.Detail(5)
  2. VoituresController.Index()
  3. HomeController.Detail(5)
  4. DetailController.Voitures(5)
Explication

Le patron {controller=Home}/{action=Index}/{id?} decoupe l'URL en trois segments. Ici Voitures designé le controller, Detail l'action et 5 le paramètre id, donc Detail(int id) est appelé avec id = 5.

QCM1 min

Que doit retourner une action quand la ressource demandée n'existe pas ?

  1. View()
  2. BadRequest()
  3. RedirectToAction(...)
  4. NotFound()
Explication

NotFound() produit une réponse 404. BadRequest() renvoie un 400 pour une requête invalide, alors qu'une ressource absente correspond bien a un 404.

QCM1 min

Quelle responsabilité n'a pas sa place dans un controller ?

  1. Choisir la view à rendre
  2. Exécuter du SQL ou des calculs métier
  3. Lire les paramètres de la requête
  4. Renvoyer un code 404 si besoin
Explication

Le controller orchestre, il ne fait pas le travail métier. Le SQL et les calculs appartiennent au model et aux services. C'est l'application de Single Responsibility à l'architecture web.

QCM1 min

Comment un controller reçoit-il l'implémentation d'un service enregistre dans le conteneur ?

  1. En instanciant la classe concrète avec new
  2. En appelant une méthode statique du service
  3. En declarant l'interface comme paramètre du constructeur
  4. En lisant une variable globale
Explication

On declare l'interface dans le constructeur, par exemple VoituresController(IVoitureService service), et ASP.NET injecte l'implémentation enregistrée. Le controller dépend de l'abstraction, pas de la classe concrète.

QCM1 min

Quel lifetime crée une nouvelle instance par requête HTTP, partagée entre les services d'une même requête ?

  1. Singleton
  2. Transient
  3. Scoped
  4. Static
Explication

Scoped donne une instance par requête HTTP, réutilisée par tous les services de cette requête. C'est le choix typique pour un DbContext ou un contexte utilisateur, et le défaut le plus sur en cas de doute.

QCM1 min

Pour un repository en mémoire enregistre en Singleton avec un état mutable, quel point demande de la vigilance ?

  1. La thread safety, car l'instance est partagée par toute l'application
  2. Rien, le conteneur gère automatiquement les verrous
  3. Le recreer manuellement à chaque requête
  4. Éviter de l'injecter dans un controller
Explication

Un Singleton vit du premier usage jusqu'au shutdown et sert toute l'application. Si son état est mutable, plusieurs requêtes concurrentes y accèdent en parallèle : la thread safety devient obligatoire.

QCM1 min

Le principe Single Responsibility énoncé qu'une classe doit avoir...

  1. Une seule méthode publique
  2. Une seule propriété
  3. Une seule raison de changer
  4. Un seul constructeur
Explication

Le S de SOLID dit qu'une classe ne doit avoir qu'une seule raison de changer, pas dix. Cela ne limite pas le nombre de méthodes ou de propriétés, mais le nombre de responsabilités.

QCM1 min

Que recommandé le principe d'inversion des dépendances (D de SOLID) ?

  1. Dépendre toujours des classes concrètes
  2. Regrouper tout le code dans une grosse interface
  3. Éviter les interfaces pour simplifier
  4. Dépendre d'abstractions, pas d'implémentations
Explication

Dependency Inversion demande de dépendre d'abstractions plutôt que d'implémentations concrètes. C'est exactement ce que rend possible l'injection de dépendances via les interfaces.

QCM1 min

De quelle classe une exception métier comme VehiculeIndisponibleException devrait-elle hériter ?

  1. ArgumentException
  2. Exception
  3. NullReferenceException
  4. IOException
Explication

Les exceptions métier héritent de Exception, avec un suffixe en Exception et un constructeur acceptant un message (idéalement une innerException). Les classes comme NullReferenceException ou IOException couvrent des erreurs techniques du framework.
