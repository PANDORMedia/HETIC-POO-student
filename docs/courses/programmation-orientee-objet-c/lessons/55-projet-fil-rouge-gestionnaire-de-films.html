Projet fil rouge : gestionnaire de films

slidesDurée : 30 min

La flotte sur le web

Tu reprends la flotte de location modélisée en console et tu la sors sur le web avec ASP.NET Core MVC. Le domaine reste le même (vehicules, voitures, motos, réservations), seule la presentation change : des pages HTML rendues par des contrôleurs au lieu d'un menu console.

Le perimetre

Fonctionnalités

  • Liste de la flotte.
  • Detail d'un vehicule (fiche).
  • Ajout, modification, suppression d'une voiture via des formulaires.
  • Reservation avec calcul de tarif.

Contraintes

  • Réutiliser tes classes du domaine (Vehicule, Voiture, Moto, etc.).
  • Persistance JSON sur disque.
  • Validation cote serveur.
  • Injection de dépendances partout où c'est utile.

Architecture proposée

Quatre couches, chacune dependant uniquement de l'abstraction de la couche du dessous (principe DIP) :

CoucheRôleDépend de
Views RazorAffichage, Razor + ViewModelsrendues par les contrôleurs
ControllersOrchestration HTTPIVoitureService
IVoitureServiceRègles métier, calcul du tarifIVoitureRepository
IVoitureRepositoryPersistance JSONle domaine
DomainVehicule, Voiture, Moto, Reservationrien

Comme chaque couche ne connait que l'interface du dessous, tu pourras remplacer la persistance JSON par SQL plus tard sans toucher au reste.

Phases du projet

  1. Setup : projet ASP.NET Core MVC crée, domaine copie depuis la console, premier run.
  2. Lecture : VoituresController avec Index et Detail, données en dur, views Razor.
  3. Écriture : Create, Edit, Delete avec formulaires, validation par DataAnnotations, redirections.
  4. DI et persistance : IVoitureRepository, VoitureRepositoryJson, injection dans Program.cs.
  5. Reservation : formulaire de reservation, ITarifCalculator injecte, calcul affiche.

Bonus : pagination, recherche, gestion des autres types de vehicules.

Critères d'évaluation

Fonctionnel

  • L'application tourne sur localhost.
  • Phases 1 a 4 atteintes au minimum.
  • CRUD complet sur Voiture fonctionnel.
  • La persistance JSON survit au redémarrage.

Architecture

  • Domaine réutilise sans modification liée au web.
  • Services et repository injectes via une interface.
  • Pas de logique métier dans les contrôleurs.
  • Validation cote serveur avec DataAnnotations.
  • ViewModels distincts du domaine quand c'est pertinent.

Pour voir l'architecture MVC en action avant de demarrer, regarde la demo aspnet-mvc.
