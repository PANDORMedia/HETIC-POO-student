Démo guidée : application web MVC

codingDurée : 25 min

Objectif de la demo

Cette demo guidee reprend chaque couche d'une application web ASP.NET Core MVC sur l'exemple d'un site de location de voitures. On part de la structure du projet, on suit une requête de l'URL jusqu'à la vue, puis on branche les services par injection de dépendances. Le code complet est disponible dans demos/aspnet-mvc, et la version commentée pas a pas se trouve sur la demo aspnet-mvc.

1. Anatomie d'un projet ASP.NET Core MVC

Un projet MVC range le code selon trois rôles : les contrôleurs orchestrent, les modèles portent les données, les vues affichent. La structure type ressemble a ceci.

LocationWeb/
  Controllers/
    HomeController.cs
    VoituresController.cs
  Models/
    Voiture.cs
  Views/
    Home/        Index.cshtml
    Voitures/    Index.cshtml  Detail.cshtml
    Shared/      _Layout.cshtml
  wwwroot/       css/  js/  lib/
  Program.cs
  appsettings.json
  LocationWeb.csproj

Pour créer puis lancer le projet :

dotnet new mvc -n LocationWeb
cd LocationWeb
dotnet run

Au démarrage, l'application ecoute sur https://localhost:5001 et sert une page d'accueil par défaut. Le rechargement a chaud met la page à jour des qu'un fichier est sauvegarde.

2. Routing : de l'URL vers l'action

La convention de routage par défaut associe une URL a une méthode de contrôleur en trois segments.

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");

Si un segment manque, on retombe sur les valeurs par défaut, soit Home/Index. Voici comment les URL se traduisent en appels.

RequêteAction appelée
GET /HomeController.Index()
GET /VoituresVoituresController.Index()
GET /Voitures/Detail/5VoituresController.Detail(5)
POST /Voitures/CreateVoituresController.Create(form)
GET /Voitures/Edit/5VoituresController.Edit(5)

L'URL /Voitures/Detail/5 appelle Detail(int id) de VoituresController avec id = 5. Le rapprochement est automatique.

3. Contrôleurs et actions

On écrit une classe de contrôleur par ressource. Chaque action retourne un résultat qui sera traduit en réponse HTTP.

public class VoituresController : Controller
{
    public IActionResult Index()
    {
        var voitures = _service.Lister();
        return View(voitures);
    }

    public IActionResult Detail(int id)
    {
        var voiture = _service.LirePar(id);
        if (voiture == null) return NotFound();
        return View(voiture);
    }
}

Les types de retour les plus courants :

  • View() : rend une vue Razor.
  • RedirectToAction(...) : redirige vers une autre action.
  • Json(...) : renvoie une charge utile JSON.
  • NotFound() : réponse 404.
  • BadRequest() : réponse 400.

Règle a tenir : pas de SQL ni de calcul métier dans le contrôleur. Il orchestre les appels, il ne fait pas le travail lui-même.

4. Vues Razor

Une vue reçoit un modèle type et le presente en HTML. Le fichier Index.cshtml de la liste des voitures :

@model List<Voiture>
<h1>Voitures</h1>
<ul>
@foreach (var v in Model)
{
    <li>
        <a asp-action="Detail" asp-route-id="@v.Id">
            @v.Marque @v.Modele
        </a>
    </li>
}
</ul>

Le strict nécessaire en Razor :

  • @variable : interpolation d'une valeur.
  • @if (...) { ... } : conditionnel.
  • @foreach (...) { ... } : itération.
  • @model T : type du modèle reçu par la vue.
  • asp-action, asp-route-* : tag helpers qui generent les liens.

Le fichier _Layout.cshtml contient le gabarit commun a toutes les pages. L'appel @RenderBody() indique l'emplacement ou s'insere le contenu de chaque vue.

5. Le conteneur de services

Les dépendances sont enregistrees dans Program.cs, puis injectées là où on en a besoin. Chaque enregistrement choisit une duree de vie : AddSingleton pour une instance unique, AddScoped pour une instance par requête, AddTransient pour une instance à chaque demande.

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllersWithViews();

// Tes services
builder.Services.AddSingleton<IVoitureRepository, VoitureRepositoryJson>();
builder.Services.AddScoped<IVoitureService, VoitureService>();
builder.Services.AddTransient<ITarifCalculator, TarifStandard>();

var app = builder.Build();

Du cote du contrôleur, on declare l'interface dans le constructeur. ASP.NET fournit l'implémentation enregistrée, sans que le contrôleur connaisse la classe concrète.

public class VoituresController : Controller
{
    private readonly IVoitureService _service;

    public VoituresController(IVoitureService service)
    {
        _service = service;
    }

    // ... actions
}

Cette déclaration par interface rend le contrôleur testable et indépendant de la manière dont les voitures sont stockées.
